# 项目成绩单与证据等级

这张表只汇总已经有运行记录支持的结果。生产规模、控制流测试和模型准确率是三种不同证据，不混为一谈。

## 1. 真实生产规模

| 模块 | 真实运行结果 | 能说明什么 |
|---|---:|---|
| Gallica ALTO OCR缓存 | 13,057页 | 工作流处理过真实大规模馆藏数据 |
| ContentSearch / Pagination缓存 | 2,399 / 1,131份 | 检索与页码映射不是人工逐页复制 |
| 议会候选事件 | 3,921项 | 高召回发现层进入过长期生产 |
| 本地私人档案 | 294张扫描、72份历史文件 | 系统能先分件，再按文件识读 |
| 本地档案相关性 | A 14份、B 46份、C 12份 | 问题意识分级已用于真实档案盒 |
| 本地档案边界 | 64份high、7份medium、1份low | 不确定性被显式保存 |
| 本地档案模型调用 | 260次，合计约4.0926美元 | 费用可逐次审计并受硬预算控制 |

私人档案生产运行覆盖37次主边界判断、10次疑难边界复核、96个转写批次、117个翻译批次。最终校验确认294张扫描全部得到归属、没有扫描页被重复分配、A/B类转写和译文均已生成；研究分析阶段仍有未完成项，因此原运行没有被包装成“全项通过”。

## 2. 模型诊断指标

在7个研究者完整整理的议会事件种子上：

| 方法 | Schema通过率 | 身份一致率 | 等级一致率 | 事件页IoU | Landry发言页覆盖率 | 回应关系F1 |
|---|---:|---:|---:|---:|---:|---:|
| 规则＋命中页±1 | 100% | 57.1% | 0% | 0.550 | 0.714 | 0.143 |
| DeepSeek Prompt v1 | 85.7% | 100% | 0% | 0.373 | 0.750 | 0.348 |
| DeepSeek Prompt v2 | 100% | 100% | 100% | 0.864 | 0.964 | 0.543 |

这些是小样本诊断结果，不是正式泛化准确率。它们证明Prompt v1把“本人发言”误当“完整事件”的问题可被错误分析定位，并通过任务定义修正；也暴露出回应关系仍然是最难的能力。

30条真实议会样本的DeepSeek v2运行全部得到结构化响应，输入489,928 token、输出5,557 token，平均延迟2.25秒，估算费用0.0633美元。由于30条标签尚未全部由研究者签字，不能把它们包装成正式Gold准确率。

## 3. 工程验证

- 25项自动化测试通过；
- 覆盖Gallica查询扩展、分页、缓存修复、漏检审计、事件合并；
- 覆盖本地档案哈希保护、路径迁移、显式手稿路由、模型失败回退、费用记录和断点复用；
- 模拟端到端测试确认同一运行重复启动不会重复付费调用已经成功的任务。

## 4. 当前不能宣称的内容

- 不能宣称“所有Gallica材料零漏检”：原始OCR和馆藏索引本身可能缺失；
- 不能宣称“手稿识读达到某个准确率”：尚未建立逐字人工金标准；
- 不能把模型置信度直接解释为正确率；
- 不能把7个事件种子的诊断指标外推到所有人物、年代和馆藏。

这些限制不是免责声明，而是评测设计的一部分：系统把失败、疑难项和证据不足显式交给研究者，而不是把它们隐藏在一个总分里。
