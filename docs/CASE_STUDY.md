# 案例：从Gallica姓名命中到可引用的Landry议会事件

## 1. 业务问题

法国史研究者面对的并非单纯“找不到OCR工具”，而是官方数字档案的馆藏记录、整期文献、文内命中页和完整历史事件彼此分离。以Adolphe Landry为例，检索结果可能是正式发言、插话、他人提及、法案署名、表决名单、目录或OCR误识别；单个命中页也常常看不到他在回应谁、谁回应了他以及议案最后如何处理。

因此，本案例把任务定义为：**在尽量不漏掉材料的前提下，判断命中是什么，并恢复“最小但语义完整”的议会事件。**

## 2. 工作流设计

系统先通过Gallica SRU发现文献，再用ContentSearch定位文内命中，通过Pagination恢复官方印刷页码，以ALTO取得逐页OCR。Python完成缓存、去重、姓名变体和明显材料类型初筛；模糊样本再交给模型判断人物身份、材料类型、相关性和边界。

事件边界不是固定截取若干页。系统从命中页前后各一页开始，分别检查：

- 是否包含议题或程序背景；
- 是否保留Landry的完整发言及其回应对象；
- 是否包含对Landry的直接回应；
- 是否出现表决、延期、散会或下一议题等结束信号。

只缺一侧时仅向该侧扩展。达到扩展上限仍不确定的材料保留为宽边界或候选事件，并进入review queue，而不是被静默删除。

## 3. 真实运行证据

早期API试点在1929—1933年获得340条具有ARK的发现记录。随后选取10个具有代表性的边界案例进行校准，发现“ContentSearch命中簇”并不等于“一场辩论”：其中既有需要拆分为多个条款事件的材料，也有目录指向正文、历史引述、部长提交文本和当前正式发言。

第一批7个复杂事件完成了从原始OCR到法中对照、发言顺序、回应关系、页码和脚注的端到端整理。公开样例选用1931年2月24日法国参议院关于工资单“职业资格”的讨论：两页文本完整保留议题提出、Courtier的疑问、委员会说明、Landry以劳动部长身份答复、Courtier接受解释以及法案通过。

更大规模生产中，系统已形成13,057页ALTO OCR缓存，并处理588份战后法国参议院官方PDF。上述数字证明工作流能够批量运行，但**不被用作模型准确率**；模型质量需由独立人工金标准评测。

## 4. 标注与评测意义

这个案例将历史学家的隐性判断转化为可标注字段：人物身份、材料类型、A/B/C/D等级、事件起止、发言范围、回应关系和人工复核状态。评测的目的不是证明模型“懂历史”，而是回答三个产品问题：

1. 哪些样本可以自动处理，哪些必须人工复核；
2. 错误来自任务定义、Prompt、输入上下文、工作流还是模型能力；
3. 在DeepSeek、千问、GPT及规则基线之间，哪种质量—成本组合适合生产。

当前仓库公开的是30条分层Pilot候选集、标注规范和评测协议。只有研究者最终确认的样本才进入正式准确率；机器或既有流程生成的标签不会冒充金标准。
